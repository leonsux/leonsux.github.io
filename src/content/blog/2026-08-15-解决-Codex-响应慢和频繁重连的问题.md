最近使用 Codex Desktop 时，我遇到了两个很影响体验的问题：响应明显变慢，以及界面频繁出现 `Reconnecting 5/5`。有时重连后能恢复，有时则需要等待很久，任务经常被打断。

![Codex 从 Reconnecting…1/5 连续重试到 Reconnecting…5/5 的示意图](/img/codex-proxy/reconnecting-sequence.svg)

结合修改前后的结果，我判断：至少在我的环境中，问题和 Codex 没有稳定使用本地代理有关。为 Codex 显式配置代理地址后，响应速度和连接稳定性都明显改善。

![Codex 通过本地代理连接 OpenAI 的链路示意图](/img/codex-proxy/proxy-flow.svg)

## 解决方法

打开用户目录下的 `~/.codex/.env` 文件，加入以下两行配置：

```dotenv
HTTP_PROXY=http://127.0.0.1:7897
HTTPS_PROXY=http://127.0.0.1:7897
```

![Codex 代理环境变量配置示例](/img/codex-proxy/env-config.svg)

这里的 `7897` 是我使用的代理软件所提供的本地代理端口。你的端口不一定相同，请以代理软件中显示的 HTTP 或 Mixed 端口为准。

`HTTPS_PROXY` 的值写成 `http://127.0.0.1:7897` 并不矛盾。这里的协议表示 Codex 如何连接本地代理，并不代表最终访问的目标只能使用 HTTP。

保存文件后，完全退出 Codex，再重新启动。仅关闭当前窗口可能不会让新的环境变量生效。

## 实际效果

重启后，Codex 的响应速度恢复正常，频繁出现的 `Reconnecting 5/5` 也基本消失了。

这套方法更适合下面这种情况：

- 代理软件已经开启，浏览器访问相关服务也正常；
- Codex 仍然响应缓慢，或者频繁断线重连；
- 系统代理没有被 Codex 稳定读取。

需要注意的是，代理软件必须保持运行。如果本地代理没有启动，或者端口号已经变化，Codex 反而会因为无法连接代理而失去网络。

这篇文章记录的是我在当前版本中的实际解决过程。OpenAI 的公开环境变量文档目前没有专门说明这一组 Codex Desktop 配置，因此后续版本如果调整了代理读取方式，应以最新官方说明为准：[Environment variables](https://learn.chatgpt.com/docs/config-file/environment-variables)。

## 总结

如果 Codex 响应慢，并且反复出现 `Reconnecting 5/5`，可以先检查它是否真正使用了本地代理。在 `~/.codex/.env` 中显式配置 `HTTP_PROXY` 和 `HTTPS_PROXY`，然后彻底重启 Codex，是一个简单且有效的排查方向。
